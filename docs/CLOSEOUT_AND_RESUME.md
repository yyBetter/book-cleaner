## 1. 为什么先做阶段收尾（实测硬件瓶颈复盘）

本阶段已完成全栈工程与端到端闭环开发，自动化测试（48 项全通过）、前后链路导出、多表模板与浏览器真实交互全部跑通。决定先做阶段收尾、暂缓上线推广的核心客观原因只有一条——**现有主力电脑算力不足以支撑真实复杂纸面的高精度离线视觉识别**：

1. **轻量 CPU OCR 精度天花板**：内置 `RapidOCR (PP-OCRv4)` 与 `PP-OCRv5` 适合清晰印刷体和规整单据；但面对密集格线表格、手写混排、折痕、微弱泛黄涂改时，文字漏识/错识率仍偏高。
2. **本地视觉大模型算力限制**：实测 16 GB 内存（核显/系统保留后可用约 `15.5 GB`）、无大显存 NVIDIA 独立显卡的轻薄本/办公本，虽然能在参数校验与内存体积上装载 `GLM-OCR 0.9B` / `Qwen2.5-VL 3B`（已修复 15.5 GB 内存容差并通过 `300s` 超时与异常显性回退保护），但在实际业务页上**纯 CPU 推理耗时过长，高并发/批量翻拍吞吐跟不上现场节奏**；同时 `DeepSeek-OCR 2 CUDA` 本地旗舰包硬性依赖 `>= 8 GB` 显存的 NVIDIA GPU。

因此将截至目前的全部成果完整固化、标注里程碑并归档，后续一旦具备更匹配的算力环境或接入策略即可一键恢复迭代。

## 2. 本阶段已沉淀的五大核心能力总览

### ① 采集与光学前处理（`1 拍照`）
- **采集多端接入**：Windows DirectShow 高拍仪/USB 摄像头直采、浏览器直采、Android 手机（USB ADB 通道 / Wi-Fi `--auto-https` 零存储直传）、本地扫描图片与多页 PDF 批量导入，支持双侧压书手自动避让防抖抓拍与边缘手指擦除。
- **物理级图像洗净**：双页拆单（L/R）、透视切边、书页弯曲展平、泛黄/阴影漂白（洁净彩页 / 锐利灰度 / Sauvola 黑白二值）、`±20°` 连续纠偏，以及基于文字方向检测的 **离线 `0° / 90° / 180° / 270°` 四向自动扶正 + 手动 `90°` 旋转重识**。
- **采集即质检 & 废片管理**：毫秒级模糊、过暗、过曝、dHash 连拍重复页告警；胶片条倒序展示、`×` 秒删废片、清空整书与两步删除书目。

### ② 4 页签统一光学复核台（`1 拍照 ➔ 2 复核 ➔ 3 表格 ➔ 4 导出`）
- 原先分散的「进度」与「复核」已收口合并为统一的 **`2 复核`** 双栏工位，顶部可折叠展示全书 4 步加工摘要与进度条。
- **坐标锚定双向联动**：支持 `原图` / `成片` / `拉帘` 三模式切换与滚轮缩放；右侧渲染 Markdown 文本/表格悬停或点击时，左侧纸面原位自动橙框锚定对应文本块（olmOCR 风格坐标锚定），支持 `渲染对照` / `编辑 MD` 切换与 `复制 MD`。
- **GFM Markdown 表格重构**：按文本块列坐标聚类还原标准 GFM 管道符表格（`| 列1 | 列2 |`），并适配 `2 复核` 在线表格渲染、数据清洗拆分及 EPUB XHTML `<table>` 输出。
- **防误锁交互**：全局弹窗与工作台面板实现滚动固定顶底栏，OCR 回退与超时异常显性告警（不再静默），支持实时处理加载态与快速跳过/批量清理异常废片。

### ③ 涉密严格离线锁与 6 档离线 OCR 模型中心
- **默认涉密防泄漏**：`ocr.strict_offline = true` 默认锁定，拦截一切发往非本机 `127.0.0.1 / localhost` 的外发识别/精校请求；针对 Windows 本机 Ollama 调用统一设置 `trust_env=False` 绕过系统代理/VPN 劫持。
- **硬件体检与 6 档引擎矩阵**：自动识别 CPU、内存（含 Windows 核显保留容差）、磁盘、NVIDIA 显存与本地 Ollama 服务，统一管理以下 6 档离线引擎（含断点暂停/续传/取消/卸载与一键设为主引擎）：
  1. `RapidOCR`（内置 PP-OCRv4，零下载纯 CPU 秒级）
  2. `PP-OCRv5` 轻量增强包（`~21 MB` 纯 CPU）
  3. `PP-OCRv5` 高精度包（`~165 MB` 纯 CPU 推荐）
  4. `GLM-OCR 0.9B`（本机 Ollama，表格/手写小钢炮）
  5. `Qwen2.5-VL 3B`（本机 Ollama，复杂语义与涂改手写）
  6. `DeepSeek-OCR 2` 旗舰 CUDA 本地隔离包（需 NVIDIA `>= 8 GB` 显存）
- 支持 `hybrid_smart` 混合升级策略（低置信度与复杂表格页自动升档），以及离线/内网回环 `300s` 长超时适配。

### ④ 多 Sheet 模板包、可校验清洗与 CatBoost 衔接（`3 表格` & `4 导出`）
- **三栏可视化分拣台**：左侧模板 Sheet 抽屉 ➔ 中间页面人工/关键词自动归属（支持别名自学习）➔ 右侧字段连线对齐、写入预览与子表 Schema（含多目标 `y`）配置。
- **预置三大商业多表模板包 + 自有模板导入**：开箱即带通用多表批次记录（含多目标 CatBoost）、实验室研发记录本、财务凭证与合同台账 3 套样板，并支持一键上传任意多 Sheet 空 `.xlsx` 识别表头。
- **可校验稽核与 PII 脱敏**：支持字段级物理上下限与相邻值 `>5` 倍突变标黄告警拦截；支持导出前跨 **Excel / Markdown / JSONL / PDF / EPUB** 一致性敏感词与 PII（手机号、身份证、邮箱等 + 自定义词）脱敏掩码。
- **多格式输出**：多 Sheet `.xlsx`（自动附带 `异常待复核`、`清洗汇总报告`、`CatBoost_特征宽表` 与 `CatBoost_字段契约`）、可搜索 PDF、Markdown、EPUB 3 与 RAG JSONL。

### ⑤ 商业化打包与 Windows 一键部署底座
- **纯离线 Ed25519 授权体系**：内置本机硬件机器码（`SS-XXXX-XXXX-XXXX`）与零联网 Ed25519 签名验证（未激活体验版单次限制导出前 5 页；自用开发可通过环境变量 `BOOK_CLEANER_ENFORCE_LICENSE=0` 放行）。
- **Windows 开箱资产**：`start_windows.bat` / `start_windows_https.bat`（三国内镜像自适应 + 离线秒开兜底）、系统托盘启动器（`superscanner-desktop`）、打包脚本与 Inno Setup 安装脚本、HTML/JS `Cache-Control: no-cache` 防缓存更新机制。

## 3. 后续重启的 3 条算力路径建议

待后续重新启用本项目时，可根据现场保密要求与预算直接任选其一接入：

| 方案路径 | 适用场景与硬件门槛 | 预期效果与操作方式 |
| :--- | :--- | :--- |
| **路径 A：单机高配纯离线**（涉密首推） | Windows 配备 **`>= 12 GB` 显存 NVIDIA 独显**（如 RTX 3060 12G / 4070 / 4080），或 **24～32 GB+ 统一内存 Apple Silicon** | 下载 `DeepSeek-OCR 2 CUDA` 旗舰包，或在 GPU Ollama 上流畅运行 `GLM-OCR` / `Qwen2.5-VL 7B`，单页秒级出字且全离线 |
| **路径 B：局域网私有 GPU 服务**（企业多工位） | 公司内网部署一台独立 GPU 服务器运行 vLLM / Ollama（OpenAI 兼容 Vision 接口），普通 16 GB 办公本仅跑扫描前端 | 在前端指向内网服务器 IP，多台低配电脑共享一张显卡算力，数据不出内网（若需放行局域网私有 IP，在界面关闭外发限制或按内网白名单调整校验） |
| **路径 C：非涉密云端混合**（零硬件投入） | 纸质资料允许经合规授权后调用外部 API，保持 16 GB 轻薄本不变 | 在右上角 `OCR 设置` 关闭 **「涉密严格离线模式」**，填入云端 DeepSeek-OCR 2 / 视觉大模型 API，开启 **`hybrid_smart` 混合升级**按页按需调用 |

## 4. 下次重启快速恢复清单

1. **拉取同步环境**（Windows / macOS 通用）：
   ```bash
   git pull origin main
   uv sync --no-dev
   ```
2. **运行全套自动化回归检查**：
   ```bash
   uv run --no-sync pytest -v
   ```
3. **本地自用免页数限制启动**：
   - Windows CMD：
     ```bat
     set BOOK_CLEANER_ENFORCE_LICENSE=0
     start_windows.bat
     ```
   - macOS / Linux：
     ```bash
     BOOK_CLEANER_ENFORCE_LICENSE=0 uv run --no-sync book-cleaner serve --host 0.0.0.0 --port 8765
     ```
